# جلسه اول پایتون پیشرفته

**موضوع جلسه:** آماده‌سازی محیط توسعه، محیط مجازی پایتون و کار با Git و
GitHub

در این جلسه با ابزارهایی آشنا شدیم که برای مدیریت اصولی پروژه‌های پایتون
و همکاری تیمی به آن‌ها نیاز داریم. هدف این است که از همان ابتدای دوره،
پروژه‌ها را تمیز، قابل‌مدیریت و قابل‌اشتراک‌گذاری نگه داریم.

## سرفصل‌های جلسه

1.  آشنایی با Git و کاربرد آن در مدیریت نسخه‌های پروژه
2.  آشنایی با مخزن (Repository) و مفهوم Commit
3.  ایجاد مخزن در GitHub و اتصال پروژه محلی به آن
4.  ارسال تغییرات پروژه به GitHub با دستور `push`
5.  آشنایی با محیط مجازی (Virtual Environment) و دلیل استفاده از آن
6.  ساخت و فعال‌سازی محیط مجازی در پروژه پایتون
7.  آشنایی با فایل `.gitignore` و جلوگیری از ارسال فایل‌های غیرضروری به
    مخزن

## دستورات مهم

### بررسی نسخه پایتون و Git

``` bash
python --version
git --version
```

### ساخت محیط مجازی

``` bash
python -m venv .venv
```

### فعال‌سازی محیط مجازی در ویندوز

در CMD:

``` bat
.venv\Scripts\activate.bat
```

در PowerShell:

``` powershell
.venv\Scripts\Activate.ps1
```

برای خارج شدن از محیط مجازی:

``` bash
deactivate
```

### چند دستور پرکاربرد Git

``` bash
git init
git status
git add .
git commit -m "first commit"
git remote add origin YOUR_REPOSITORY_URL
git branch -M main
git push -u origin main
```

> به‌جای `YOUR_REPOSITORY_URL` آدرس مخزن خودتان در GitHub را قرار دهید.
> اگر مخزن از قبل به `origin` متصل شده است، دستور
> `git remote add origin` را دوباره اجرا نکنید.

## ساختار پیشنهادی پروژه

``` text
python-advanced-session-01/
│
├── .venv/              # محیط مجازی؛ نباید وارد Git شود
├── .gitignore
├── README.md
└── main.py
```

محتوای پیشنهادی فایل `.gitignore`:

``` gitignore
.venv/
venv/
__pycache__/
*.py[cod]
.env
.idea/
.vscode/
```

## تمرین‌های جلسه اول

تمرین‌ها را به‌ترتیب انجام دهید. برای هر تمرین یک پروژه یا پوشه جداگانه
بسازید و در پایان، کدها و فایل‌های لازم را در GitHub قرار دهید.

### تمرین ۱: ساخت اولین مخزن

1.  پوشه‌ای با نام `python-advanced-session-01` بسازید.
2.  داخل آن فایل `main.py` ایجاد کنید.
3.  برنامه‌ای بنویسید که نام و سن کاربر را دریافت کند و یک پیام
    خوشامدگویی نمایش دهد.
4.  با Git یک مخزن محلی ایجاد کنید.
5.  تغییرات را Commit کنید و مخزن را به GitHub بفرستید.

**هدف:** تمرین ساخت Repository، ثبت Commit و Push کردن پروژه.

### تمرین ۲: محیط مجازی مستقل

1.  پروژه‌ای با نام `calculator-project` بسازید.
2.  برای آن یک محیط مجازی با نام `.venv` ایجاد کنید.
3.  محیط مجازی را فعال کنید.
4.  یک فایل `main.py` بسازید که دو عدد را از کاربر دریافت کند و جمع،
    تفریق، ضرب و تقسیم آن‌ها را نمایش دهد.
5.  مطمئن شوید پوشه `.venv` در GitHub ارسال نمی‌شود.

**هدف:** درک کاربرد محیط مجازی و جداسازی فایل‌های محیط توسعه از کد پروژه.

### تمرین ۳: مدیریت تغییرات با Git

1.  در پروژه تمرین اول، یک قابلیت جدید اضافه کنید.
2.  وضعیت مخزن را با `git status` بررسی کنید.
3.  فقط فایل تغییرکرده را به مرحله آماده‌سازی Commit اضافه کنید.
4.  یک Commit با پیام معنادار ثبت کنید.
5.  تغییرات را به GitHub ارسال کنید.

**هدف:** تمرین چرخه مشاهده تغییرات، Add، Commit و Push.

### تمرین ۴: اصلاح پروژه و ثبت نسخه جدید

برنامه‌ای بنویسید که سه نمره را از کاربر دریافت کند و میانگین آن‌ها را
نمایش دهد.

-   ابتدا نسخه ساده برنامه را Commit کنید.
-   سپس برنامه را طوری تغییر دهید که اگر ورودی نامعتبر بود، پیام مناسبی
    نمایش دهد.
-   تغییر دوم را در یک Commit جداگانه ثبت کنید.
-   هر دو نسخه را به GitHub بفرستید.

**هدف:** درک این موضوع که Git تاریخچه تغییرات پروژه را نگه می‌دارد.

### تمرین ۵: پروژه کوچک مدیریت اطلاعات

برنامه‌ای با نام `student_manager` ایجاد کنید که اطلاعات یک دانشجو را از
ورودی دریافت کند:

-   نام و نام خانوادگی
-   شماره دانشجویی
-   رشته تحصیلی
-   سه نمره

برنامه باید اطلاعات را مرتب نمایش دهد و میانگین نمرات را محاسبه کند.

**شرایط تحویل:**

-   پروژه دارای محیط مجازی مستقل باشد.
-   فایل `.gitignore` داشته باشد.
-   فایل `README.md` شامل توضیح کوتاه پروژه باشد.
-   پروژه در GitHub قرار گرفته باشد.
-   حداقل سه Commit با پیام‌های مناسب داشته باشد.

## نکات مهم

-   پوشه محیط مجازی (`.venv`) را در GitHub ارسال نکنید.
-   قبل از Commit کردن، خروجی `git status` را بررسی کنید.
-   برای هر تغییر مهم، یک Commit جداگانه با پیام واضح ثبت کنید.
-   اطلاعات محرمانه مانند رمز عبور، کلید API و فایل‌های `.env` را در مخزن
    عمومی قرار ندهید.
-   نام فایل‌ها و پوشه‌ها را انگلیسی و خوانا انتخاب کنید.

## نحوه تحویل تمرین‌ها

لینک مخزن GitHub خود را طبق زمان اعلام‌شده توسط مدرس ارسال کنید. مخزن
باید شامل کدهای پروژه، فایل‌های راهنما و فایل `.gitignore` باشد.

**یادآوری:** هدف این تمرین‌ها فقط نوشتن چند خط کد نیست؛ می‌خواهیم از همین
ابتدا عادت کنیم پروژه‌های پایتونی را با ساختار مناسب و مدیریت نسخه اصولی
توسعه دهیم.
